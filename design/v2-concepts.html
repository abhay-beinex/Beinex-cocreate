Beinex Co-Create · design v2 · 5 November 2026

Four screens, one concept each

These are redesigns, not polish passes. Each concept states the one job of the screen, the regions it gets (never more than three), and what the person can now do that they could not before. Visual language stays claymorphism with a touch of glass: clay for the main panel only, flat inner elements, hairline dividers, floating glass for palettes and inspectors.

Concept 1

Home is an inbox and a pulse

The job: tell me what needs me, what is running, and let me start anything in one line. Not a greeting with lists under it.

  • Region 1 · Start line. One composer with an intent switch: Ask, Build an agent, Build a workflow. Typing routes to Chat, Studio or the builder with the text carried over.
  • Region 2 · Needs you. Approvals and failed runs with inline Approve / Reject / Run again. Running runs show a live step bar. Empty state is one quiet sentence.
  • Region 3 · Pulse. 14-day run activity, failures, spend today against the cap, then a tabbed workspace list (Agents · Workflows · Recent runs).
  • First run replaces region 2 with a three-step setup card that disappears when done.

Concept 2

Chat has threads, not one chat per agent

The job: work with any agent over many conversations, bring your own files, and turn good answers into things (documents, workflows).

  • Region 1 · Threads. New chat, search, threads grouped Today / Yesterday / Earlier, each showing its agent. Rename and delete.
  • Region 2 · Conversation. Wide, calm column. Openers are the agent's sample prompts. Every answer has quiet actions: copy, save as document, turn into a workflow. Sources collected under the answer.
  • Composer. Agent pill switches the agent for this thread, thinking level (Fast / Balanced / Deep), attach a text file as context.
  • Gated actions still queue under Approvals and say so inline.

Concept 3

Studio starts with a brief, not a wizard

The job: get from a sentence to a complete, testable agent in two moves. Describe it; the assistant drafts everything; review on one page; create.

  • Step 1 · Brief. One large composer: who it helps, what it must do, what it must never do. Example briefs as chips. Templates as a row of starting points. Import JSON stays as a quiet link.
  • Draft. "Draft the agent" asks the Co-Create Assistant for name, description, icon, abilities, thinking, independence, personality, instructions, sample prompts and three test cases. Progress shows what is being written.
  • Step 2 · Review. Everything on one scrollable page as editable sections, with the live card on the left. Create as draft, or Create and test (opens the agent page on Test drive).
  • The old four-step path stays reachable as "Build step by step" for people who prefer it.

Concept 4

Builder is canvas-first with a real assistant panel

The job: see the whole flow, edit one step at a time, talk to the assistant like a colleague, and watch runs where the steps are.

  • Canvas. Full bleed. A floating glass header holds name, status, Checks, Save, Test, Publish. A slim glass toolbar on the left: Add step (opens a searchable palette: Steps, Abilities, Connectors), Assistant, Tidy up.
  • Inspector. A floating glass panel on the right for the selected step. New: variable key badge, Input template with a variable picker, retries and "if it fails", "Try this step" with the last run's variables.
  • Co-Create Assistant panel. Toggled from the toolbar; 380px wide; a conversation. Builds, extends, explains a failed run, fixes checks. Changes are shown as a plan ("Add 3 steps, connect after Research") with Apply.
  • Run drawer. Slides up from the bottom: a horizontal timeline of steps with lanes for loop items and parallel branches, outputs on click, Variables tab, Run again from here.
  • New steps: Repeat for each, Split, Run code, Call an API, Run a workflow; conditions get a rule mode; triggers get By link, When a page changes, When a document is added.

What stays the same

Vocabulary (Abilities, Thinking, Independence, Personality), the governed model (external actions wait for a person), the empty workspace, one demo user, models chosen by level, and the sidebar. Notifications are reduced to approvals, failures and schedule problems.
